# K&R Exercise 1.11 — тестирование программы подсчёта слов

Упражнение 1.11 посвящено не написанию нового алгоритма, а **тестированию программы подсчёта строк, слов и символов** из предыдущего примера K&R.

Основная задача — придумать такие входные данные, которые с наибольшей вероятностью выявят ошибки в программе.

---

## Проверяемая программа

Программа использует два состояния:

```c
#define IN  1
#define OUT 0
```

и считает словом последовательность символов, отделённую:

- пробелом `' '`;
- табуляцией `'\t'`;
- переводом строки `'\n'`.

То есть граница слова определяется только этими тремя символами.

---

# Что нужно тестировать

При тестировании важно проверять не только обычный ввод:

```text
hello world
```

но и граничные случаи:

- пустой ввод;
- пустые строки;
- один символ;
- одно слово;
- несколько разделителей подряд;
- пробелы в начале и конце;
- табуляции;
- несколько переводов строк подряд;
- отсутствие `'\n'` перед `EOF`;
- различные комбинации разделителей;
- знаки препинания.

---

# Набор тестов

## 1. Пустой ввод

Ввод:

```text
EOF
```

Ожидаемый результат:

```text
lines = 0
words = 0
chars = 0
```

`EOF` не является символом входного потока и не учитывается в количестве символов.

---

## 2. Пустая строка

Ввод:

```text
\n
```

Ожидаемый результат:

```text
lines = 1
words = 0
chars = 1
```

Символ `'\n'` учитывается как один символ.

---

## 3. Одно слово без перевода строки

Ввод:

```text
abc
```

затем `EOF`.

Ожидаемый результат:

```text
lines = 0
words = 1
chars = 3
```

Отсутствие `'\n'` перед `EOF` не мешает корректно посчитать последнее слово.

---

## 4. Одно слово с переводом строки

Ввод:

```text
abc\n
```

Ожидаемый результат:

```text
lines = 1
words = 1
chars = 4
```

---

## 5. Только пробелы

Ввод:

```text
"   "
```

Ожидаемый результат:

```text
words = 0
chars = 3
```

Количество строк зависит от наличия `'\n'`.

---

## 6. Несколько пробелов между словами

Ввод:

```text
one     two
```

Ожидаемый результат:

```text
words = 2
```

Количество пробелов между словами не должно влиять на число слов.

---

## 7. Пробелы в начале и конце

Ввод:

```text
"   one   "
```

Ожидаемый результат:

```text
words = 1
```

Начальные и конечные разделители не создают дополнительных слов.

---

## 8. Табуляции

Ввод:

```text
one\t\t\ttwo
```

Ожидаемый результат:

```text
words = 2
```

Несколько символов `'\t'` подряд должны работать так же, как несколько пробелов.

---

## 9. Несколько пустых строк

Ввод:

```text
\n\n\n
```

Ожидаемый результат:

```text
lines = 3
words = 0
chars = 3
```

---

## 10. Слова на разных строках

Ввод:

```text
one

two
```

Ожидаемый результат:

```text
lines = 3
words = 2
```

Пустая строка между словами не создаёт дополнительного слова.

---

## 11. Комбинация разных разделителей

Например:

```text
one \t  \n two
```

Проверяется корректность переходов между состояниями `IN` и `OUT`.

Ожидаемое количество слов:

```text
2
```

---

## 12. Один символ

Ввод:

```text
a
```

затем `EOF`.

Ожидаемый результат:

```text
words = 1
chars = 1
```

---

# Знаки препинания

Программа K&R считает границами слов только:

```c
' '
'\t'
'\n'
```

Поэтому:

```text
one,two
```

будет считаться **одним словом**.

А:

```text
one, two
```

— двумя словами.

То же касается:

```text
hello.world
hello-world
hello;world
```

В рамках алгоритма K&R это не ошибка, а следствие выбранного определения слова.

Если требовалось бы считать слова естественного языка, алгоритм пришлось бы расширять.

---

# Backspace и терминал

При интерактивном вводе нажатие Backspace может обрабатываться драйвером терминала ещё до того, как символ попадёт в `getchar()`.

Поэтому такой тест не всегда проверяет именно программу.

Например:

```text
abc<Backspace>d
```

может фактически попасть в программу уже как:

```text
abd\n
```

Если необходимо проверить настоящий символ `'\b'`, его лучше подать через pipe или файл.

Например:

```bash
printf 'ab\bcd\n' | ./Ex_1_11.out
```

Тогда во входном потоке действительно будет присутствовать символ `'\b'`.

При этом для исходного алгоритма K&R `'\b'` не является разделителем слова, поскольку разделителями считаются только:

```c
' '
'\t'
'\n'
```

---

# EOF

`EOF` не является обычным символом.

В цикле:

```c
while ((c = getchar()) != EOF) {
    ++nc;
}
```

значение `EOF` используется только как признак окончания входного потока.

Поэтому оно:

- не учитывается в количестве символов;
- не считается словом;
- не считается строкой.

Например, если вход содержит:

```text
abc
```

и затем сразу приходит `EOF`, программа получает только:

```text
'a'
'b'
'c'
```

Поэтому:

```text
chars = 3
words = 1
lines = 0
```

---

# Что именно проверяет упражнение

Главная идея упражнения — научиться искать ошибки через **набор граничных входов**, а не только через обычный пример.

Особенно важно проверять переходы состояний:

```text
OUT → IN
IN  → IN
IN  → OUT
OUT → OUT
```

Например:

```text
"word"
```

проверяет:

```text
OUT → IN
IN → IN
```

Ввод:

```text
"word "
```

проверяет:

```text
OUT → IN
IN → OUT
```

Ввод:

```text
"   "
```

проверяет:

```text
OUT → OUT
```

А ввод:

```text
"one   two"
```

проверяет несколько переходов:

```text
OUT
 ↓
IN
 ↓
OUT
 ↓
OUT
 ↓
OUT
 ↓
IN
```

# Обнаруженные ограничения

Явной ошибки в алгоритме подсчёта слов на проверенных входах обнаружено не было.

Однако алгоритм использует очень простое определение слова.

Границами считаются только:

```c
' '
'\t'
'\n'
```

Поэтому:

```text
hello,world
```

считается одним словом.

Аналогично:

```text
hello.world
hello;world
hello:world
```

также будут считаться одним словом.

Это не ошибка реализации относительно алгоритма из книги, а **ограничение выбранной модели слова**.

---

# Отличие пустой строки от пустого ввода

Эти случаи визуально похожи, но для программы принципиально различаются.

## Пустой ввод

Сразу приходит:

```text
EOF
```

Результат:

```text
lines = 0
words = 0
chars = 0
```

---

## Пустая строка

В поток поступает:

```c
'\n'
```

а затем `EOF`.

Результат:

```text
lines = 1
words = 0
chars = 1
```

То есть `'\n'` является настоящим символом входных данных, а `EOF` — специальным значением, сигнализирующим об окончании ввода.

---

# Вывод

На проверенных входных данных исходная программа K&R корректно работает в рамках своей модели слова.

Очевидных ошибок в логике подсчёта слов обнаружено не было.

Главное ограничение алгоритма:

> словом считается последовательность символов, разделённая только пробелом, табуляцией или переводом строки.

Знаки препинания не считаются разделителями.

Таким образом, упражнение показывает не столько необходимость найти конкретный баг, сколько важность систематического тестирования.

При тестировании следует проверять:

```text
обычный случай
        +
граничные случаи
        +
пустой ввод
        +
минимальный ввод
        +
повторяющиеся разделители
        +
переходы между состояниями
        +
окончание потока
```

Главный вывод упражнения:

> Недостаточно проверить программу на одном нормальном примере. Нужно пытаться подобрать такие входные данные, которые заставят программу пройти через все важные состояния и граничные условия.

Этот подход применим не только к учебным программам на C, но и к embedded-разработке: парсерам протоколов, UART-потокам, конечным автоматам, сетевым пакетам и обработке данных из периферии.
